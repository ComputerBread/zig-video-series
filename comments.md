## write good comments

comments should be use to indicate things that are difficult or impossible to
know when reading the code.

- state of mind
- tradeoff
- purpose, why the code is doing something

they can be used to explain obscure/difficult to understand lines of code

- sometimes, it can be hard to tell what a line does, comments to describe what

warnings

- don't delete this

can be used as documentation

- when writing libraries, comments can be used by tools to create documentation

## avoid bad comments

- describing what the code is doing, if it's already obvious
